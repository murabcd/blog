## A Better Prompt Can Still Use the Wrong Source

An agent receives a precise task and follows the wrong reference implementation because an old design note appears beside the current one. Another prompt revision may change the wording of the answer without fixing the source selection.

Treat the full input as something the system constructs: instructions, retrieved material, tool definitions, conversation history, and task state. Each part can help, conflict, or distract. The work is to select what the current decision needs and establish which source has authority.

## Choose What the Decision Needs

Putting more material in the context can give an agent the evidence it needs. It can also introduce an obsolete implementation, a conflicting instruction, or ten pages that have little to do with the task. A larger window gives the system room to include information; the system still needs a way to choose and interpret it.

Start with the evidence required for the next decision. Include enough surrounding detail to interpret it, identify which source is current, and test whether the agent uses it correctly. Removing useful context can cause a failure too, so evaluate the selection against actual tasks rather than treating a shorter input as a success by itself.

## An Architecture for Effective Context

For a practical starting point, separate the input into instructions, domain material, and working state. They answer different questions: what may the agent do, what does it need to know, and what has already happened?

**1. Define the Task and Its Boundaries**

Describe the intended result, the evidence required, and the conditions for asking a person to take over. Tone instructions can help shape the answer, but they do little to resolve a missing policy or an unclear escalation rule.

Consider an AI agent designed for financial compliance queries. The "rules of engagement" would be a detailed specification:

-   **Persona:** "You are a professional compliance assistant. Your tone is formal, precise, and cautious."
-   **Objective:** "Your goal is to answer user questions by citing specific clauses from the provided regulatory documents."
-   **Guardrails:** "You must never provide legal advice or speculate on regulations not present in the provided knowledge base. If you cannot find a direct answer, you must escalate to a human compliance officer."

These instructions describe the intended policy. Enforce access and action boundaries outside the model where possible, and evaluate whether the assistant cites the right material and escalates when evidence is missing.

**2. Supply Relevant Domain Material**

Retrieve the records and documents needed for the task, with enough provenance to assess them. Examples can also show what an acceptable result looks like when a prose instruction leaves too much open to interpretation.

Imagine building an AI-powered sales assistant. Its domain expertise comes from the context provided:

-   **RAG:** The agent is connected to Salesforce to retrieve real-time data about a specific customer's account, and to an internal wiki to pull relevant case studies and product documentation.
-   **Few-shot Examples:** The context includes a handful of "gold standard" examples of what a great follow-up email looks like, demonstrating the ideal tone, structure, and inclusion of relevant data points.

Keep the roles of those inputs clear. An example email can demonstrate tone and structure; the current account record should supply the customer facts. Copying a detail from the example into the customer's email would be a context failure even if the writing looked right.

**3. Preserve Working State**

A task that spans several sessions needs a durable record of progress. Store completed work, unresolved decisions, and the evidence behind them so the agent can resume without reconstructing everything from a long conversation.

For a codebase migration, keep a compact task record and let the agent inspect relevant files as it reaches each part of the work:

-   **Structured Note-Taking:** Keep task progress in a dedicated state file with completed steps, key decisions, and next actions. Reserve `AGENTS.md` for durable workspace instructions so temporary progress does not acquire the authority of a standing rule. Load the relevant state when resuming work.
-   **Agentic Search:** The agent doesn't have the entire project folder in its context. Instead, it has a tool that can search the file system. When it needs a specific utility function, it actively searches, reads it, and loads only that specific document into its context for that specific task.

This mirrors how an effective engineer works. They don't keep every detail in their head; they use an external system of notes and files to retrieve information as needed.

## Context Is the Architecture

The input an agent sees is the result of product and engineering decisions: what to retrieve, which source to trust, what state to retain, and what to leave out. Those decisions shape the answer before the model begins producing it.

Treating that work as part of the architecture changes where the team looks when something fails. A polished instruction can sit on top of a system that supplies the wrong evidence. Improving the wording alone leaves that system in place.
