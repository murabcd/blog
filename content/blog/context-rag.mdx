## The Answer with Missing Conditions

A support assistant retrieves the right export instructions and still gives an unhelpful answer. It lists the steps for free and enterprise accounts together, ignores how much data the customer needs, and leaves them to work out which path applies.

There are two different gaps here. The retrieved text may have lost its surrounding document context, and the system may lack the customer's current account state. Adding context to chunks can help with the first. The second requires the right information about the person asking.

## Why Chunk Boundaries Matter

A chunk can contain a procedure while leaving its prerequisites in the previous section. It can mention “the limit” without naming the plan or version the limit applies to. Semantic similarity may retrieve the passage because it contains the right words, even though the answer needs the missing conditions.

Consider a hypothetical export guide with these passages:

- The interface provides a Data Export action in Settings.
- Free accounts have a record limit per export.
- Enterprise accounts can use an API for larger exports.

Returning all three passages is better than inventing an answer. To recommend an action, the assistant still needs to know the account type, the intended export size, and whether the customer can use the API. Retrieval and user-state handling should be evaluated separately.

## Preserve the Document Context

Contextual retrieval adds a short explanation of a chunk's place in the source before indexing it. That explanation can identify the product, section, version, audience, or surrounding process when those details are supported by the document.

A contextualized passage might identify itself as the export procedure for a particular plan and link back to the full section. This helps retrieval distinguish it from similar procedures elsewhere. Do not let the generated explanation introduce a plan entitlement or prerequisite that the source never states.

## Implementing Contextual Retrieval

Start with a baseline index and a set of representative questions. For each chunk, generate a short description using the source document, then review a sample before indexing the enriched text.

A preprocessing prompt can be explicit about the boundary:

```text
Read the document and the selected passage.
Describe the passage's topic and its place in the document.
Include relevant product, audience, version, and prerequisites
only when the source establishes them.
Do not add facts or instructions absent from the document.
Return only the short context description.
```

Store the source text and generated context separately so they remain distinguishable. Use the enriched representation for indexing, preserve source links, and decide which parts the answering model should receive. Regenerate the context when the underlying document changes.

## Measure the Indexing Tradeoff

In its [2024 contextual retrieval experiments](https://www.anthropic.com/research/contextual-retrieval), Anthropic reported a 35% relative reduction in top-20 retrieval failures with contextual embeddings. Combining them with contextual BM25 produced a 49% reduction in that evaluation. Those are results from a particular benchmark, not a promised improvement for every knowledge base.

Preprocessing adds model calls and indexed text. It can change index size, retrieval behavior, and the amount of text passed to the answering model. Measure those costs with your own documents rather than assuming that query latency or overall cost remains unchanged.

## When the Extra Context Helps

Try this approach when chunk meaning depends on definitions elsewhere in the document, repeated terminology refers to different products, or a procedure has important prerequisites. A self-contained collection may gain less from generated context and may work well with headings and metadata alone.

Use failure cases to choose. If the expected passage never appears in the results, investigate indexing and retrieval. If it appears but the answer misapplies it, inspect the generation instructions, source interpretation, and user state.

## Add Structure before More Generation

Document titles, heading paths, version tags, and source timestamps can supply useful context without an extra model-generated explanation. Compare those additions with contextual generation rather than assuming every chunk needs another paragraph.

Query-specific expansion can also help retrieve related material, but it introduces another stage to evaluate. Keep the baseline available so you can tell which change improved the result.

## Test the Answer against the Task

Use real questions and inspect whether the final answer lets someone complete the intended work. Check the cited source, the conditions under which the advice applies, and what the assistant does when account information is missing.

A better retrieval score is useful evidence. The release decision should also depend on whether the answer preserves those conditions and asks for clarification when it needs it.
